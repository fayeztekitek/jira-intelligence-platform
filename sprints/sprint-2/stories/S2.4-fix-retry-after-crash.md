# S2.4 — Fix Retry-After Crash

## Description

The `Retry-After` header sometimes returns non-integer values (e.g., HTTP-date
strings like `Wed, 21 Oct 2015 07:28:00 GMT`). The code tried `int()` on the
raw value, causing a `ValueError` crash during rate-limit handling.

## Acceptance Criteria

- [x] `Retry-After` header parsed safely for both integer seconds and HTTP-date
- [x] Fallback to default retry delay (60s) when parsing fails
- [x] Rate-limit handling continues without crashing

## Implementation Notes

- Use `email.utils.parsedate_to_datetime()` for HTTP-date format
- Wrap in try/except with fallback

## Files Changed

- `backend/jira_connector/client.py` — fixed Retry-After parsing in retry handler

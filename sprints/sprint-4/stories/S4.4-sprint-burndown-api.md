# S4.4 — Sprint Burndown API Endpoint

## Description

Create `GET /api/sprints/{id}/burndown` that returns daily remaining points
for a given sprint, enabling the frontend burndown chart.

## Acceptance Criteria

- [ ] Endpoint accepts sprint ID and project ID
- [ ] Returns array of `{date, remaining_points, ideal_points}`
- [ ] ideal_points = linear from commitment to 0 over sprint duration
- [ ] remaining_points computed from changelog (daily resolved count)
- [ ] Cache result for 1 hour (sprint data doesn't change intra-day often)

## Implementation Notes

- Query `FactTransition` for resolution events during sprint
- Group by date, compute cumulative resolved
- Ideal line: starting at commitment, decreasing linearly

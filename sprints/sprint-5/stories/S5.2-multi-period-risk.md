# S5.2 — Multi-Period Risk Scoring

## Description

Currently `RiskScorer` only computes risk for `1m`. Extend to compute for `1w`, `1m`, and `3m` windows using appropriate KPIResult data for each period.

## Acceptance Criteria

- [ ] `RiskScorer.compute()` accepts `period: str` parameter
- [ ] For `1w`, aggregates last 7 days of KPI data
- [ ] For `3m`, aggregates last 90 days of KPI data
- [ ] `KPIResult` filter adjusted per period when computing risk
- [ ] Backwards compatible — default period remains `1m`

## Implementation Notes

- In `scorer.py`, change `compute()` signature to `compute(db, project_key, period="1m")`
- Use the period to filter KPIResult rows by matching `period_label`
- Store period on `RiskScore` model (add `period_label` column or reuse `period_type`)

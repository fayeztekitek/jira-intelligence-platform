# S7.9 — Rate Limiting on AI Endpoint

## Description

Add per-user rate limiting to the AI chat endpoint to prevent abuse and
control LLM API costs. Limit: 20 requests per minute per user.

## Acceptance Criteria

- [ ] Rate limiter checks user ID from JWT claims
- [ ] 20 requests per minute window per user
- [ ] Returns 429 Too Many Requests with `Retry-After` header
- [ ] Uses Redis for distributed rate limiting (fallback to in-memory)
- [ ] Configurable: `AI_RATE_LIMIT` env var
- [ ] Burst allowance: up to 5 additional requests if bucket has capacity

## Implementation Notes

- Token bucket algorithm: refill 20 tokens per minute, max 25
- Redis: key = `rate_limit:ai:{user_id}`, value = token count + timestamp
- In-memory fallback: dict-based token bucket per user

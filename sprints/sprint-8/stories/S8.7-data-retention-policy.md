# S8.7 — Data Retention Policy

## Description

Implement configurable data retention policies per table. Old data is
either purged or archived to cold storage (CSV/Parquet files).

## Acceptance Criteria

- [ ] `DATA_RETENTION_DAYS` env var maps table → retention days
- [ ] Defaults: FactIssue=730 (2y), FactSnapshot=365 (1y), RiskScore=365, AuditLog=90
- [ ] Daily cleanup job: delete rows older than retention period
- [ ] Archive option: before deletion, export to compressed CSV in `/data/archive/`
- [ ] Archive files named: `{table}_{date_from}_{date_to}.csv.gz`
- [ ] Archived files restorable via CLI tool
- [ ] Retention policy configurable per table via admin API

## Implementation Notes

- Archive format: gzipped CSV with header row
- Cleanup runs as part of nightly maintenance job in `jobs.py`
- Archive path configurable via `ARCHIVE_PATH` env var

## Files Changed

- `backend/config.py` — add DATA_RETENTION_DAYS settings
- `backend/scheduler/jobs.py` — add retention cleanup job
- `backend/storage/repositories.py` — add purge and archive methods

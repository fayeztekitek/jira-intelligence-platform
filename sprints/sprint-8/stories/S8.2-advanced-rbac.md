# S8.2 — Advanced RBAC

## Description

Replace the simple admin/non-admin JWT model with role-based access control:
`viewer`, `analyst`, `admin` roles with per-project permissions stored in DB.

## Acceptance Criteria

- [ ] `User` DB table: id, username, email, role, is_active
- [ ] `Role` enum: viewer, analyst, admin
- [ ] `ProjectPermission` table: user_id, project_id, role (overrides global role)
- [ ] Viewer: can view dashboards and KPIs
- [ ] Analyst: can export data, use AI agent
- [ ] Admin: can configure connections, manage users, view audit logs
- [ ] Permission check middleware: verifies user has access to requested project
- [ ] Admin dashboard for user management
- [ ] Default admin user created on first startup

## Implementation Notes

- JWT claims include `user_id`, `role`, `projects` (list of accessible project IDs)
- Permission checked on every route: `require_access(project_id, min_role="analyst")`
- Migration 004 creates User + ProjectPermission tables

## Files Changed

- `backend/storage/models.py` — add User, ProjectPermission tables
- `backend/api/auth.py` — add role/permission checking, user CRUD
